# Antigravity Unlocker для Mac

Для Mac с Apple Silicon (серия M) и с процессором Intel. Рекомендуемая версия системы — macOS 13 или новее.

## Установка

1. Скачайте `Psychotic_AG_Fork.dmg` со страницы релизов и дважды нажмите на него. Откроется окно с приложением **Antigravity Unlocker** и ярлыком **Applications**.
2. Перетащите **Antigravity Unlocker** на ярлык **Applications**.
3. Откройте **Antigravity Unlocker** из папки «Программы», через Launchpad или Spotlight. На вкладке **«Обзор»** нажмите **«Проверить»**, чтобы увидеть состояние установленных клиентов.

Вместо образа можно взять архив `AG_<версия>_macOS_universal_app-local.zip`: дважды нажмите на него и перенесите распакованное приложение в «Программы».

## Первый запуск

Приложение подписано без сертификата Apple. Поэтому при первом открытии скачанной копии macOS может сообщить, что не может проверить разработчика, и не открыть её. Тогда:

1. Откройте **Системные настройки → Конфиденциальность и безопасность**.
2. Внизу, рядом с сообщением об Antigravity Unlocker, нажмите **«Всё равно открыть»** и подтвердите.

Это нужно один раз для каждой новой версии. Вместо этого можно один раз выполнить команду в Терминале:

```sh
xattr -dr com.apple.quarantine "/Applications/Antigravity Unlocker.app"
```

## Разрешение «Управление приложениями» (обязательно)

Antigravity установлен в `/Applications`, а macOS (начиная с Ventura) защищает приложения в этой папке: без специального права анлокер **не может изменить файлы Antigravity**, то есть патч не накладывается и деактивация не проходит.

**Признаки, что не хватает именно этого права:**

- в разделе **«Установки»** у «Antigravity · настольное приложение» стоит **«Патч не подтверждён»**, а переключатель «Разблокировка входа» не доходит до зелёного;
- в карточке вверху окна — **«macOS не даёт пропатчить Antigravity»**;
- при нажатии **«Полная деактивация»** появляется ошибка и патч остаётся на месте;
- в журнале фоновой службы `~/.local/share/agunlocker/watchdog.log` есть строка **«macOS не даёт записать»**: после обновления Antigravity служба не смогла наложить патч. Она повторяет попытку раз в 5 минут, так что после выдачи права патч ляжет сам;
- `--status` (см. ниже) пишет под файлом **«macOS не даст записать»**.

**Как выдать право:**

1. Откройте **Системные настройки → Конфиденциальность и безопасность → Управление приложениями**.
2. Включите в списке:
   - **Antigravity Unlocker** — само приложение. Фоновая служба автопатча запускается из копии этого же приложения, поэтому в списке может быть две строки «Antigravity Unlocker» — включите обе;
   - **Терминал** — только если вы запускаете анлокер из него. Тогда служба называется **`ag_watchdog`** (в версиях до 2.35.1 — **`ag_proxy`**), включите и её.
3. Если службы ещё нет в списке — один раз откройте анлокер и включите автопатч (служба тогда появится), затем включите её и повторите действие.
4. Вернитесь в анлокер и снова нажмите **«Включить всё»** (или **«Полная деактивация»** для отката).

Если после установки новой версии анлокера macOS снова не даёт записать, выключите и снова включите его переключатель в этом списке.

## Запуск из Терминала

Бинарник лежит внутри приложения, его можно запускать с ключами:

| Режим | Команда |
|---|---|
| Текстовый интерфейс | `"/Applications/Antigravity Unlocker.app/Contents/MacOS/ag_unlocker" --tui` |
| Проверка без изменений: установки, патч, служба | `"/Applications/Antigravity Unlocker.app/Contents/MacOS/ag_unlocker" --status` |
| Версия | `"/Applications/Antigravity Unlocker.app/Contents/MacOS/ag_unlocker" --version` |

`--status` ничего не меняет и не закрывает: только печатает найденные установки, состояние патча каждого файла и фоновой службы. Его вывод удобно приложить к сообщению об ошибке. Код выхода: 0 — всё пропатчено, 1 — не всё, 2 — установки не найдены.

## Запасной вариант: папка с `Запустить.command`

Архив `AG_<версия>_macos.tar.gz` содержит голый бинарник `ag_unlocker` и скрипт `Запустить.command`. Распакуйте архив, оставьте оба файла рядом и дважды нажмите **Запустить.command**: откроются Терминал и окно анлокера. Право «Управление приложениями» в этом случае нужно Терминалу. Если Терминал пишет `No such file or directory`, проверьте командой `ls`, что в текущей папке видны оба файла.
